## 3. Gate 6에서 한 일

1. **첫 발사 멈춤 제거.**
   - 원인: 사격 이펙트(탄, 착탄, 폭발) 셰이더가 처음 쓰일 때 컴파일된다. 첫 발사 프레임이 **118ms**였다.
   - 조치: 시작 메뉴가 떠 있는 동안 양 팀 이펙트를 한 번 그려 컴파일을 끝내고, 즉시 소멸시킨다(`Game.warmUpEffects`).
   - 처음 시도한 워밍업은 효과가 없었다. 메뉴 중에는 `effects.update`가 돌지 않아 탄과 자국이 실제로 그려지지 않았기 때문이다. 동기 렌더를 한 번 하도록 고쳤다.
   - 결과: 첫 발사 구간의 최악 프레임이 **11–15ms**다(새로 로드한 페이지 3회 측정).
2. **자동 해상도** (`settings/ResolutionGovernor.ts`, 설정 "자동 해상도 (프레임 유지)", 기본 켜짐).
   - 낮추는 조건: 최근 2초 동안 20ms를 넘는 프레임이 20%를 넘으면 렌더 해상도를 한 단계 내린다(100% → 85% → 72%).
   - 되돌리는 조건: 최근 6초 동안 모든 프레임이 15ms 이하이면 한 단계 올린다.
   - 올린 직후 다시 느려지면 30초 동안 올리지 않는다(진동 방지).
   - 품질 프리셋(그림자·효과)은 바꾸지 않는다. 플레이 중(포인터 잠금)에만 동작하며, HUD에 `RES 85%`처럼 표시한다.
   - 단위 테스트 5개.
3. **측정 방법 정정.**
   - Gate 3–5 기록의 큰 편차(medium 7–18ms, low가 medium보다 느림)는 **측정 탭이 백그라운드 상태여서** 생긴 것으로 확인했다. 백그라운드에서는 rAF가 1Hz로 떨어지는 것도 확인했다.
   - 이번 측정부터는 탭을 앞으로 가져온 뒤 같은 조건에서 3회 측정했다.

## 4. 성능 (최종)

### 4-1. 로컬 봇 30명 (최악 조건)

- 조건: 클라이언트가 봇 29명의 AI와 시뮬레이션까지 직접 돌린다. 땅 높이 카메라.
- 측정: `measurePerf.js` 3회. 값은 update + render + `gl.finish` 동기 시간이다.

| 품질 | 평균 ms (3회) | p95 ms (3회) | p95 중앙값 | 드로우콜 | 삼각형 | VRAM |
|---|---|---|---|---|---|---|
| low | 2.7 / 2.9 / 3.1 | 4.6 / 5.5 / 4.6 | **4.6** | 78–86 | 40–44k | 53MB |
| medium | 3.4 / 3.4 / 3.9 | 5.0 / 5.3 / 5.3 | **5.3** | 114–115 | 145k | 74MB |

- **medium: p95 5.3ms로 1차 목표(16.7ms)와 여유 목표(15ms)를 모두 통과했다.**
- **high: 평균은 6ms지만 p95가 17–25ms로 미통과다.** 일부 프레임의 스파이크(그림자 2단 캐스케이드와 post full로 추정)가 원인이다. legacy 리그도 25.3ms로 같으므로 아바타 때문은 아니다. high에서 스파이크가 계속되면 자동 해상도가 해상도를 낮춘다.
- GLB 아바타는 legacy보다 드로우콜이 적다(medium 115 vs 127, high 206–219 vs 251). VRAM은 약 20MB 더 쓴다(아틀라스와 병합 메시 캐시).

## 6. 남은 문제 (숨기지 않고 기록)

1. **high 품질 p95 미통과**(17–25ms 스파이크). legacy 리그에서도 같다. 그림자 캐스케이드와 post full의 비용을 나눠 측정하고 조정해야 한다.
2. **시작 시 메인 스레드가 약 1.7–1.8초 멈춘다**(Gate 3-B에서 측정, legacy와 같음). 하늘·절차 텍스처·맵 생성이 원인이다. 이번에는 고치지 않았다.
3. **KTX2/Basis와 Draco는 넣지 않았다.**
   - 아바타 텍스처는 아틀라스 1장(1536×1024)뿐이다.
   - 의상 GLB 81개는 합쳐서 약 3MB다.
   - 로더 지원을 검증하는 비용 대비 이득이 작다고 판단했다.
4. **렌더 스케일 50%와 75%에서는 따로 측정하지 않았다.** 자동 해상도의 동작은 단위 테스트로만 검증했다.
5. **실제 키 입력 검증이 없다.** 헤드리스 브라우저에는 포인터 잠금이 없어서 1~4 무기 키, Enter 채팅 같은 실제 키 입력은 같은 함수를 직접 호출하는 방식으로만 확인했다.
6. **맵 모듈 키트는 절차적 박스와 원기둥이다.** Blender 모듈 GLB는 만들지 않았다. 라이트맵과 AO 베이크도 하지 않았다.
7. **발 미끄러짐이 남는다.** 6–8m/s에서는 발 미끄러짐을 완전히 없앨 수 없다(발 고정 IK 없음). 표정은 LOD0에서만 바뀐다.
8. **온라인 테스트용 봇은 모두 기본 외형으로 보인다.**

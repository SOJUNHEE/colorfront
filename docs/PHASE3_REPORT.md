## 3. 실행

```powershell
cd C:\Users\user\Desktop\fps\colorfront
npm run start:server     # 게임 서버 ws://127.0.0.1:2567  (/health, /metrics)
npm run dev              # 클라이언트 http://localhost:5173 → 닉네임 → "온라인 매치 참가"
```

- 짧은 시험 경기는 `http://localhost:5173/?mode=online&seconds=60`으로 연다(개발 빌드 전용).
- 부하 테스트는 `npm run load -- --players 30 --seconds 60`이다.

## 4. 실제 두 브라우저 검증

### 4.1 방법
- **브라우저:** 별도의 Chrome 프로세스 2개(A=Alice, B=Bob)를 띄웠다. 프로필, 저장소, WebSocket이 모두 따로다.
  - headless 모드지만 실제 GPU(ANGLE/D3D11)로 60 FPS 렌더링한다.
  - 처음에는 창 모드로 했지만, 창이 최소화되거나 가려지면 브라우저가 10 FPS로 제한해서 결과가 오염됐다.
- **입력:** 이동·사격·점프·대시·준비는 실제 키보드·마우스 이벤트로 했다.
  - Pointer Lock은 자동화로 얻을 수 없어서 대체 처리했다.
  - 시선은 마우스 이동이 들어가는 입력 객체에 직접 설정했다.
- **스크립트:** `tests/visual/twoBrowser/1-setup.js` ~ `5-reconnect-results.js`. 아래 수치는 **최종 코드로 처음부터 끝까지 다시 실행한 결과**다.

## 6. 성능

### 6.1 측정 환경
모두 한 PC에서 측정했다(Intel 내장 GPU). 같은 PC에서 서버, 클라이언트, 봇, Vite, VS Code가 함께 돌았고 CPU 부하는 약 45%였다. 그래서 단발성 지연이 생길 수 있으므로 범위로 적는다.

### 6.2 서버 (네트워크 봇 부하, `npm run load`)
| 인원 | 틱 평균 | 틱 p95 | 틱 최대 | 30Hz 예산(33ms) 초과 | 메모리 RSS | 일관성 |
|---|---|---|---|---|---|---|
| 4 vs 4 | 1.0 ms | 2.5 ms | 72 ms | 2회 | 99 MB | 8명 해시 = 서버, 결과 동일 |
| 8 vs 8 | 2.6 ms | 7.7 ms | 228 ms | 6회 | 105 MB | 16명 해시 = 서버, 결과 동일 |
| 15 vs 15 (3회) | 2.2 ~ 4.2 ms | 5.7 ~ 13 ms | 12 ~ 82 ms | 0 ~ 5회 | 109 ~ 133 MB | 30명 해시 = 서버, 결과 동일, 해시 검사 990회 불일치 0 |

- 30명에서도 평균은 예산의 약 10%다. 가끔 생기는 40~230ms 단발 지연은 인원과 관계없이 나타났다. 같은 PC의 다른 부하나 GC 때문일 수 있지만 원인은 확인하지 못했다(9장).
- 메모리 누수 점검: 30명 라운드 4번 연속 후 힙 사용량은 26 → 33 → 25 → 28MB로 늘어나지 않았다. 끝난 방은 모두 정리됐다.

## 9. 남은 문제

- **서버가 한 번 로그 없이 종료됨**(종료 코드 1). 재현되지 않았다. 지금은 프로세스 예외와 틱 예외를 기록·격리하므로, 다시 생기면 원인이 남는다.
- **단발성 틱 지연 40~230ms**가 몇 분에 한 번씩 생긴다. 배포할 서버(전용 vCPU)에서 다시 측정해야 한다.
- **"room is locked" 입장 거부가 1번 있었다.** 29명 방에 입장할 때였고, 다시 시도하니 재현되지 않았다. Colyseus는 예약된 좌석도 정원에 포함한다. 꽉 찬 방에 들어가려 할 때의 안내 문구가 필요하다.
- **브라우저 창이 최소화되거나 백그라운드에 있으면 10 FPS 이하로 떨어진다.** 이때 그 플레이어는 서버에서 제자리 대기로 처리된다(D-016). 탭 복귀를 감지해 사용자에게 알리는 기능은 없다.
- **실제 원격 네트워크(지연 50~150ms, 패킷 손실) 시험을 하지 않았다.** 서버의 `SIMULATE_LATENCY_MS` 옵션은 있지만 아직 이 조건으로 검증하지 않았다.
- **배포 전 필요한 항목:**
  - TLS(wss)
  - WebSocket Origin 검사
  - 방 목록과 매칭(공개방 최소 6명 규칙, GDD 2.1)
  - 운영용 로그와 지표 수집
  - 서버 프로세스 관리(재시작 정책)
- 동결 단계(카운트다운·결과)에서는 입력을 버린다. 그래서 그 사이 누른 키는 다음 단계로 이어지지 않는다(의도한 동작).
